# 官方开放接口版（v1.0.0-api）架构说明

> 版本标识：`app/__init__.py` → `VERSION = "1.0.0-api"`。
> 与同仓库的个人浏览器版 `1.0.0-browser` 相互独立，可分别封存、分别回滚。
> 两个版本共用同一套 domain 层（价格计算 / 优惠互斥 / 同款匹配 / 推荐规则 / 评测模型），
> 区别只在**数据从哪来**：本版走平台开放接口，浏览器版走你本地的浏览器会话。

---

## 1. 这个版本的能力边界由「平台愿意开放什么」决定

| 平台 | 需要的资质 | 拿不到时会怎样 |
|---|---|---|
| 京东 | 京东开放平台开发者资质 + 联盟推广权限（`jd.union.open.*`） | 平台状态显示「未接入」，不返回任何报价 |
| 淘宝 / 天猫 | 淘宝开放平台应用 + 淘宝客（tbk）权限 | 同上 |
| 拼多多 | 拼多多开放平台应用资质（DDK 商品推广 API） | 同上 |
| 抖音商城 | 抖音开放平台应用 + 电商/团购带货权限 | 同上 |
| B 站 | 无（公开接口解析用户提交的链接） | 仍可解析视频元数据；`BILIBILI_SESSDATA` 仅用于启用视频搜索 |

**没有资质时，个性化价格、账号可见优惠券、国补资格、店铺级售后承诺一律拿不到。**
这不是实现偷懒，是接口本身不提供。此时界面会明确写「未接入」，
演示数据与真实数据严格分离，**绝不用演示数据冒充真实报价**。

如果你需要读登录后才能看到的价格与优惠，请改用同仓库的个人浏览器版
（`../agentmart-browser/`）——那条路不依赖任何开放接口。

## 2. 代码地图

```
app/
  __init__.py       版本标识 1.0.0-api
  config.py         pydantic-settings 配置；凭据只从环境变量 / .env 读
  database.py       SQLAlchemy 2.0 异步 + SQLite；新增列由 _ADDED_COLUMNS 补齐
  schemas.py        API 层 Pydantic 模型（与 domain 层一一对应，附溯源字段）
  main.py           FastAPI 入口：CORS、耗时头、路由注册、前端静态资源托管
  domain/           纯逻辑，不依赖任何外部服务
    enums.py        平台 / 数据状态 / 优惠种类 / 条件种类 / 店铺类型 / 政策范围…
    models.py       Offer / Discount / Policy / CanonicalProduct…
    pricing.py      到手价计算：标价 → 各项优惠 → 三档合计
    stacking.py     优惠互斥与叠加组（同一叠加组只取最优，不重复减）
    matching.py     同款识别：型号 / 规格 / 版本 / 店铺类型
    recommendation.py  可解释推荐：综合首选 / 最便宜 / 售后更稳妥 + 不推荐理由
  adapters/         各平台开放接口客户端（可替换的数据源）
    base.py         BasePlatformAdapter：URL 校验、限流、错误归一化
    jd.py / taobao.py / pdd.py / douyin.py
    demo.py         演示数据源（仅在显式请求演示数据时启用，接口返回里带 demo_included）
    registry.py     平台 → adapter 注册表
  infra/            横切关注点
    http_client.py  出站 HTTP：只允许 http/https，请求前校验 host，
                    拒绝 localhost、环回、私有与保留地址（防 SSRF）
    cache.py        带 TTL 的内存缓存
    ratelimit.py    简易限流
  reviews/          评测数据
    bilibili.py     B 站视频元数据解析
    criteria.py     评测可信度判定（商业合作关系 / 是否实测 / 样本量）
    curation.py     人工整理与演示评测入库
  services/
    search_service.py  搜索编排：多平台并发 → 同款分组 → 定价 → 推荐
  routers/
    health.py / search.py / reviews.py / sources.py
```

## 3. 五档价格确定性（不混淆「看到过」和「一定适用」）

| 档位 | 含义 | 是否计入到手价 |
|---|---|---|
| 页面公开 | 商品页明示、无需任何身份条件 | 计入「确定可算」 |
| 账号券 | 已确认在你账号下、且本次可用 | 计入「确定可算」 |
| 有条件 | 页面写了条件（满减 / 品类券 / 时段），未验证你是否满足 | 只计入「含待确认」 |
| 预付定金 | 预售定金 + 尾款结构 | 只计入「含待确认」 |
| 无法核验 | 只有宣传口径、没有可核验证据 | 不计入任何一档，单独列出 |

本版的开放接口通常只能拿到第一档与部分第三档的信息，其余档位在界面上
会直接标成「无法核验」并说明原因，不会靠猜。

## 4. 安全约束（代码层面强制）

- **出站请求**：仅允许 `http` / `https`；请求前解析并校验 host，
  拒绝 localhost、环回、私有与保留地址。
- **数据库**：所有外部输入一律参数绑定，不用拼接 / format / f-string 组装 SQL。
- **凭据**：只从环境变量或密钥服务读取；源码、示例、测试里都不写可用凭据字面量。
- **页面内容**：商品描述、商家文案、用户评论一律视为不可信数据，不作为指令执行。
